# 功能支持矩阵 / Feature Support Matrix

**应用**：`com.rmmv.editor` — RPG Maker MV Editor (Android MVP)
**版本**：1.0 (debug)
**图例**：✅ MVP 可用 ｜ ⚠️ 部分可用（附限制）｜ ❌ 不支持（附原因）

> **关于本移植范围的重要前提**
> Phase 1 的 REA 静态分析证明：**RPG Maker MV 的编辑器不是 NW.js 应用，而是 Qt5/QML 原生桌面程序**。安装目录下的 `nwjs-*` 是游戏播放器。因此本 MVP 不是"把编辑器 WebView 套壳"，而是**重新实现 RPG Maker MV 的工程文件格式**，使 Android 端产出的工程能被桌面 `RPGMV.exe` 直接打开。
> 证据与完整统计见 [`android-incompatibility.json`](./android-incompatibility.json)。

## 三、存储与权限

| 项目 | 值 |
|---|---|
| 工程根目录 | `/data/data/com.rmmv.editor/files/Projects/<工程名>/` |
| Capacitor 目录 | `Directory.DATA`（= `Context.getFilesDir()`） |
| 运行时权限需求 | **无**（应用私有目录豁免 Scoped Storage） |
| 已声明权限 | `INTERNET`、`READ_EXTERNAL_STORAGE`（maxSdk 32）、`READ_MEDIA_IMAGES/AUDIO/VIDEO`（API 33+，供 ACTION_OPEN_DOCUMENT 导入用） |
| `MANAGE_EXTERNAL_STORAGE` | **刻意不申请** — MVP 不需要，且会触发 Play"所有文件访问"声明 |
| compileSdk / targetSdk / minSdk | 35 / 35 / 23 |

> **踩坑记录**：初版使用 Capacitor 的 `Directory.DOCUMENTS`，实测该值映射到**外部共享存储** `/storage/emulated/0/Documents`，在 targetSdk 35 的 Scoped Storage 下写入静默失败（`adb shell ls` 确认目录为空），工程"创建成功但打不开"。已改为 `Directory.DATA`（真正的应用私有目录），无需任何权限。

测试方式：`adb install` → `am start` → `logcat` + CDP 驱动真实 WebView 内的应用代码。

## 五、已知遗留问题

1. **自动图块形状不自动推导** — 需实现四邻/对角邻接 → shape 映射表。
2. **普通图块未提供** — 需取得 `RPGMV.exe` Qt 资源中的 set→图像绑定（安装 Ghidra/Hopper 后用 REA 深度分析，或在设备上验证）。
3. **事件命令编辑器** — 仅有追加 code 101。
4. **导入/导出工程** — 桥接已就绪，UI 未接入。
5. **素材库仅 4 张图块贴图** — `img/` 218 MB + `audio/` 162 MB 未打包。
6. **多页事件 / 事件列表侧栏** — 未实现。
